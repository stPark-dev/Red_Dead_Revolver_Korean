# 번역 검수 절차 (GPT 병행)

## 1. 검수 시트 만들기

```bash
python3 tools/review_export.py review          # review/<표>-NN.tsv, 시트당 최대 150줄
```

각 시트는 `id	en	ko` 세 칸이며, 줄바꿈은 `\n`으로 적혀 있습니다. 시트는 대상별로 나뉩니다.

| 시트 | 대상 | 비고 |
|---|---|---|
| `swat.strtbl-NN`, `lvl_*.strtbl-NN` 등 | 메뉴·HUD·튜토리얼·대사 (문자열 테이블) | 같은 원문을 공유하는 사본(`same_as`)은 시트에 한 번만 나오고, 고치면 사본도 함께 바뀜 |
| `pupshow-NN` | 컷신·동영상 자막 | 장면 파일별, 대사 순서대로 정렬 (`pupshow/<장면>/<번호>`) |
| `layout-NN` | 메뉴 레이아웃 문구 (버튼·제목) | 버튼 위치는 빌드가 번역 폭에 맞춰 다시 계산 |
| `gfx-NN` | 그림 글자 (로딩 화면 그림 등) | 한 줄 = 그림 속 라벨 하나. `\n`이 그림 속 줄바꿈 |

## 2. GPT에 줄 규칙 (프롬프트에 함께 붙이기)

```
아래 TSV는 PS2 게임 「레드 데드 리볼버」(서부극) 한국어 번역 검수 시트다.
- id와 en 칸은 절대 바꾸지 말고 ko 칸만 고친다. 줄 순서·줄 수·탭 3칸 형식을 그대로 유지한다.
- 고칠 필요가 없는 줄은 ko를 그대로 둔다. 결과는 시트 전체를 TSV로 돌려준다.
- {BTN_BD}, {ICON_2021} 같은 중괄호 토큰은 버튼 아이콘이다. 개수와 이름을 그대로 둔다.
- \n(줄바꿈)은 원문에 있을 때만 쓰고 원문과 같은 개수를 유지한다.
- 게임 글꼴에 없는 문자는 쓰지 않는다: … 대신 ..., – 대신 -.
- 말투는 서부극 대사체. 인명·지명 표기는 아래 용어집을 따른다.
- 화면 상단 안내 상자는 한 줄이 좁다(한글 약 19자). 마지막 줄에 짧은 단어 하나만 남지 않게 한다.
- pupshow(자막) 시트: 한 자막은 최대 2줄. 각 줄이 원문 줄보다 눈에 띄게 길어지지 않게 한다.
  같은 장면의 앞뒤 줄은 이어지는 대화이니 맥락을 맞춘다.
- layout(메뉴 문구) 시트: 버튼·제목이라 짧게 쓴다(원문 길이 안팎).
- gfx(그림 글자) 시트: 그림 속 정해진 칸에 그려지는 글자다. 현재 번역보다 길게 만들지 않는다.
```

용어집은 `text/glossary.json`의 approved 항목을 함께 붙입니다.

## 3. 결과 반영

GPT가 돌려준 시트를 파일로 저장한 뒤:

```bash
python3 tools/review_apply.py review/pupshow-01.tsv --dry-run   # 바뀔 줄 수만 확인
python3 tools/review_apply.py review/pupshow-01.tsv             # 반영 (여러 시트 한 번에 가능)
python3 tools/wrap_audit.py                                     # 줄바꿈 홀로 남는 단어 후보
python3 -m pytest -q && python3 tools/build_patch.py work/build/dev.iso
```

- 원래와 달라진 줄만 반영하고, 그 줄은 `needs_review` 상태가 됩니다. 그림 글자는 라벨 하나만 바뀌어도 그림 전체가 `needs_review`가 됩니다. 바뀌지 않은 줄은 상태를 그대로 둡니다.
- 아래 경우 **아무 파일도 고치지 않고** 오류를 출력합니다.
  - 모르는 id가 있을 때
  - `en` 칸이 원문과 다를 때(GPT가 줄을 밀거나 영어를 고친 경우)
  - 토큰 개수가 다르거나 글꼴에 없는 문자를 썼을 때
- 화면 폭 검사(자막 폭 600 초과, 그림 칸 넘침, 글리프 없는 글자)는 빌드에서 합니다. 빌드가 실패하면 해당 줄을 줄여서 다시 반영합니다.

주의: 시트는 만든 시점의 번역을 담습니다. 시트를 만든 뒤 같은 문장을 따로 고쳤다면, 예전 시트를 반영할 때 그 수정이 덮어써집니다. 다른 수정이 있었으면 시트를 다시 만들어 씁니다.

## 4. 검수 완료 표시

검수를 마친 항목을 `distribution_eligible`로 올리는 것은 사람이 결정합니다. 배포 빌드(`--policy release`)는 이 상태의 번역만 받습니다.
